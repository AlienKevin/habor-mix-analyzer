"""Scaling law: brier_score = -(A * flops^(-alpha) + E) per group.

The functional form is the same for every group; only the
coefficients (A, alpha, E) differ.
"""

# Per-group fitted coefficients (A, alpha, E) for the model
#   -brier_score = A * flops^(-alpha) + E
# A controls the reducible-error magnitude, alpha the scaling rate
# in compute, and E the irreducible asymptotic error.
GROUP_PARAMS: dict[str, tuple[float, float, float]] = {
    "abstract_narrative_understanding": (0.51851, 0.1913, 0.0000),
    "analogical_similarity":            (0.00000, 5.0000, 0.5390),
    "arc":                              (0.07779, 0.5886, 0.0109),
    "arithmetic":                       (0.00197, 2.7586, 0.1867),
    "conceptual_combinations":          (0.01834, 1.1154, 0.3883),
    "hellaswag":                        (0.04936, 0.7041, 0.0000),
    "hindu_knowledge":                  (0.04841, 0.0000, 0.3782),
    "mmlu":                             (0.10196, 0.0000, 0.4045),
    "parsinlu_qa_mc":                   (0.00979, 1.3808, 0.4241),
}

# Fallback coefficients (median of fitted groups) for unknown groups.
_FALLBACK = (0.05, 0.5, 0.2)


def _flops_from_point(point: dict) -> float:
    """Recover linear flops from whichever input key is provided."""
    if "flops" in point and point["flops"] is not None:
        return float(point["flops"])
    if "log_flops" in point and point["log_flops"] is not None:
        # log_flops in the dataset is base-10 log of flops.
        return 10.0 ** float(point["log_flops"])
    raise KeyError("Input point must provide 'flops' or 'log_flops'.")


def law(input_data: list[dict[str, float]], group: str) -> list[dict[str, float]]:
    """Predict brier_score from compute (flops) using a per-group power law.

    Formula:  brier_score = -(A * flops^(-alpha) + E)
    """
    A, alpha, E = GROUP_PARAMS.get(group, _FALLBACK)

    predictions: list[dict[str, float]] = []
    for point in input_data:
        flops = _flops_from_point(point)
        # Guard against non-positive flops (power with negative exponent
        # would blow up); clamp to a tiny positive number.
        if flops <= 0:
            flops = 1e-12
        reducible = A * (flops ** (-alpha)) if A > 0 else 0.0
        magnitude = reducible + E
        predictions.append({"brier_score": -magnitude})
    return predictions

# Discovered Scaling Law

## Variables

The dataset relates one input variable to one output variable, separately for
each experimental group (a benchmark name).

- **Input:** `flops` — a positive scalar denoting the (scaled) compute used
  during training.  `log_flops = log10(flops)` is provided as a derived
  feature.
- **Output:** `brier_score` — the (negated) Brier score on the benchmark; it
  is non-positive, with values closer to 0 indicating a better-calibrated
  model.

## Functional Form

For every group, the relationship between compute and Brier score is captured
by a power-law-plus-asymptote of the form

```
brier_score(flops)  =  − ( A · flops^(−α)  +  E )
```

where

- `A ≥ 0` controls the magnitude of the *reducible* error (the part that can
  be driven down by adding compute);
- `α ≥ 0` is the *scaling exponent* — how quickly the Brier score improves
  with `flops`;
- `E ≥ 0` is the *irreducible* asymptote — the residual Brier score that
  remains even with infinite compute.

This is the standard Hoffmann-/Kaplan-style "compute scaling law" rewritten
for a (negated) metric whose magnitude shrinks with increasing scale.  The
function is the same for every group; only the three coefficients differ.

## Methodology

1. **Inspection.**  Plotting `−brier_score` against `flops` (and against
   `log_flops`) per group showed a curve that decreases towards a non-zero
   floor as compute grows — the classic signature of a "reducible +
   irreducible" decomposition.

2. **Sanity checks.**  We verified `log_flops = log10(flops)` exactly and
   confirmed `brier_score ≤ 0` over the whole dataset, so we modelled the
   positive quantity `y = −brier_score`.

3. **Fitting.**  For each group we fitted

   ```
   y = A · flops^(−α) + E,    A, α, E ≥ 0
   ```

   with `scipy.optimize.curve_fit` and bounded least squares, sweeping
   several initial guesses and keeping the best (lowest RMSE) solution per
   group.  A Brier score is naturally bounded in `[0, 1]`, so we capped
   `E ≤ 1`.

4. **Evaluation.**  In-sample RMSE per group ranges from 0.017 (hellaswag,
   the cleanest scaling curve) to 0.091 (abstract_narrative_understanding,
   the noisiest), with a mean of about **0.054**.  Some benchmarks
   (`hindu_knowledge`, `mmlu`) are essentially flat over the observed
   range — the optimiser converges to `α ≈ 0`, reducing the law to a
   constant Brier score, which simply reflects that those benchmarks have
   not yet entered a scaling regime within the available compute window.

5. **Robust fallback.**  Should the predictor be queried with a group name
   that was not seen during fitting, it falls back to the median fitted
   coefficients `(A, α, E) = (0.05, 0.5, 0.2)`.

## Interpretation

- Benchmarks with a small `E` and a non-trivial `α` (e.g. **hellaswag**,
  **arc**) are the ones currently in the compute-scalable regime: more
  flops measurably reduce the Brier score and the irreducible floor is
  near zero.
- Benchmarks with a larger `E` (e.g. **mmlu**, **parsinlu_qa_mc**,
  **conceptual_combinations**) have a substantial irreducible component —
  scaling alone cannot drive the Brier score to zero on the modelled
  range.
- Cases with `α ≈ 0` (**mmlu**, **hindu_knowledge**) indicate that, over
  the compute interval covered by the data, the metric is dominated by
  noise/saturation and the law degenerates to a constant.
